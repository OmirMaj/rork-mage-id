Critical path, highlighted.

Schedule health, scored against the DCMA assessment.

The federal Defense Contract Management Agency assessment that enterprise-grade schedulers (Primavera P6, Asta Powerproject) ship as a paid module — built in here, with no P6 licence and no add-on fee. Ten of the fourteen DCMA checks run in full on your own schedule, an eleventh runs as a labelled proxy, and three do not run at all. We would rather print which is which than round the number up.

  • Running today — #1 Logic (missing predecessors and successors), #2 Leads, #3 Lags, #4 Relationship Types, #5 Hard Constraints, #7 Negative Float, #8 High Duration, #9 Invalid Dates, #10 Resources and #13 CPLI. Each is computed from data the engine already carries — the typed dependency links and their lags, the date anchors, and the total float the critical-path pass returns.
  • Running as a proxy, and labelled as one on the screen — #11 Missed Tasks. The real test compares progress against a data date; this engine has no data date, so it measures tasks that should already be running against the schedule’s own span instead. The check says so on itself, not in a footnote.
  • Not running — #6 High Float, #12 Critical Path Test and #14 BEI, and the reasons differ. #6 (float above 44 working days on more than 5% of tasks) is a small addition and simply is not built yet. #12 needs a perturbation run — push a critical activity out 600 days and confirm the finish moves with it — which is a scheduling pass we have not written. #14 BEI is baseline tasks completed divided by baseline tasks due by the data date, and this engine has no data date by deliberate design, so the denominator does not exist. We will not fake it with a slippage number and call it BEI.
  • Thresholds are tuned for residential job sizes rather than a federal megaproject — the high-duration limit in particular is well below DCMA’s 44 days, because a 30-day task on a kitchen remodel is already a problem.
  • Live overall score 0–100, plain-English failure reasons (not just “DCMA #5 failed”), and tap a check to jump to the offending tasks.

Collaborative subcontractor schedules

Subs add their daily progress directly through the client portal — no extra app, no login. The GC sees every trade's update on the master Gantt, with audit trail and who-said-what-when on every change.

  • Each sub gets a per-project portal slug, no install
  • Daily progress + delays + photos pushed to the master schedule
  • GC approval gate before any sub-driven change shifts the critical path
  • Live notifications when a sub falls behind

Weather-aware reflow — and a forecast that admits when it isn't one.

Pull the forecast for the jobsite, see which outdoor tasks are exposed, and reflow the schedule around them in one tap — with the critical path recomputed, not just the dates nudged. Every shifted task keeps the reason attached, so the owner asking "why is the deck a week late" gets an answer instead of a new date.

The part most software would hide. A weather feature is only as good as the forecast behind it, and today's builds ship without a live weather key, so days come back from a simulator instead of a weather service. We do not quietly pass those off as a forecast. Every simulated day is labelled SIMULATED WEATHER — NOT A FORECAST on the screen it appears on, and the delay log flatly refuses to record a weather delay day that has no live observation behind it — so the log stays empty rather than filling up with invented evidence. A delay record you cannot defend in a claim is worse than no record at all.

  • Outdoor-task exposure flags on the Gantt
  • One-tap reflow with full CPM recalculation and an undo
  • Live days and simulated days are visibly different, always
  • Weather delay log writes on live evidence only
