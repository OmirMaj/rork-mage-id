## 4. How work ships

1. One lane per worktree and branch (`git worktree add -b claude/<lane> /private/tmp/claude-501/<lane> origin/main`,
   symlink `node_modules` from the main checkout, copy `.env`).
2. Build with a validator that plants mutations (`scripts/validate-<lane>.ts`,
   registered in `package.json` and the ship-check chain).
3. Independent review by a fresh agent that is given the code, not the
   conclusion. Every lane this session needed fixes after review.
4. Fix, merge `origin/main`, run the full gate.
5. Migration: PGlite proof, `apply_migration`, catalog verify.
6. Edge functions: `supabase functions deploy <name> --project-ref nteoqhcswappxxjlpvap --use-api`,
   plus `--no-verify-jwt` where `supabase/config.toml` says `verify_jwt = false`.
7. Push to main (Netlify publishes the marketing site and the web app on every
   push).
8. OTA from the release worktree at `origin/main`:
   `scripts/dev/heavy.sh scripts/dev/ota.sh "<plain message>"`. It publishes
   production, checks the bundle, and mirrors to preview.
9. Native builds only when native code changed:
   `eas build --profile production --platform ios --non-interactive --auto-submit --no-wait`.
   The TestFlight upload cannot be confirmed from the terminal.

PGlite lives outside the repo; see `scripts/pgq/README.md` for the one-time
install, then
`PGLITE_DIR=~/pgq-run node scripts/pgq/<name>.mjs . --all`.
