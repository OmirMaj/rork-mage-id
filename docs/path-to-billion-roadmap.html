Strategic Roadmap · Internal + Advisor

The gap isn't the product.
It's everything between built and paid.

MAGE ID has more product than a billion-dollar app needs — ~140 screens and a genuine cost-learning moat — and a marketing message that pitches it at a 9/10 level. What it has almost none of: a public launch, proof anyone uses it, working monetization, and a growth loop that's actually running. This document sequences the fix.

Prepared 2026-08-04 Sources PostHog (180d) · live web audit · UX audit 08-03 Verdict pre-launch, not pre-product

The one-sentence reframe

A cost-learning flywheel with no users closing jobs never spins — so the highest-leverage work right now is not another feature. It's making the app launchable, trustworthy, and monetizable, then turning on the loops that feed it real contractors and real cost data.

02 — The scoreboard

The billion-dollar equation

A billion-dollar app is the product of four factors. A zero in any one zeroes the result. MAGE has the two hardest to manufacture — and is missing or has broken the two that are mostly execution.

Have it

A massive market

Millions of SMB residential contractors and remodelers. Real, underserved, software-hungry.

Have it

Product depth & a moat

Cost-learning loop + margin defense no competitor ships. The message lands. The hard part is done.

Unproven

Working monetization

0 conversions from 2 paywall views. RevenueCat webhook is still an open owner action; web key is sandbox.

Missing

A compounding loop

The growth playbook exists on paper. Nothing runs. 57 visitors in three months is a standing start.

03 — The gap map

What's missing, by tier

Ordered so that fixing a lower tier is wasted if the tier above it still leaks. Do not skip ahead.

Tier 0 · Blockers makes growth spend pointless

Fix before a single real user

  1. You're not launched.iOS — the primary platform — is TestFlight-invite-only behind a 24-hour human gate. No public App Store listing means no installs, no store-search discovery, no ratings to use as proof.
  2. Monetization is unproven and possibly unplumbed.The RevenueCat webhook + secrets are still listed as an outstanding owner action ("required or paid purchases won't unlock"). Confirm one real purchase unlocks a tier end-to-end — until then, revenue is architecturally impossible.
  3. Integrity bugs that break trust on contact.A fabricated bulkSavings figure prints in the client's estimate PDF by default; prediction/confidence defaults render invented numbers as fact; 7 money screens dead-end from search; resolveDeepLinkPath silently rewrites ~99 routes to Home — which is also why the marketing ?plan=/?trial= handoff is lost. One fix closes a product bug and a conversion leak.
Tier 1 · The engine exists on paper; nothing is running

Turn a great pitch into compounding growth

  1. Zero social proof.No testimonials, logos, review badges, case studies, or founder story. The entire site asks for trust and offers none from peers — the single highest-leverage marketing fix.
  2. The flagship moat asset is empty.The MAGE Price Index reads "still building." The most defensible, viral, SEO-able page is vaporware until seeded. Programmatic permit + license ingestion populates it and the marketplace in one build — and produces the real cost data that is the pitch.
  3. No compounding acquisition.The "Built with MAGE ID" loop and comparison pages exist, but with ~0 users nothing compounds, and there's no top-of-funnel content/SEO engine feeding the high-intent queries this ICP searches.
  4. Flying blind on activation.Only ~8 event types are instrumented. There's no defined "aha" funnel (install → create project → price a bid off your own costs → send). You can't optimize what you can't see.
Tier 2 · Subtract the counterintuitive one

Narrow the wedge — depth beats breadth

  1. 140 screens is a liability at 0 users.Billion-dollar apps win by nailing one wedge's activation, not by breadth. The UX audit already found dead-ends and orphan routes.
  2. The cold-start problem is the real product risk.The moat needs closed jobs to learn, but a new contractor has none. cost-seed handles this honestly, but the day-one path must be ruthlessly narrowed to the one aha — price one bid off your own numbers — with everything else deferred.
04 — The sequence

The path, in order

The order is the thesis: seal the bucket, prove it converts, seed the moat, then open the taps. Each phase has a single exit condition before the next begins.

1

Make it launchable

Exit: a real user can install, use, and pay — without hitting a lie or a dead end

  • Delete or compute bulkSavings; null-gate every prediction/confidence default to "—". code
  • Rebuild the deep-link resolver — one fix restores QBO OAuth, crew-claim QR, push notifications, and the marketing plan/trial handoff. code
  • Give the 7 dead-end money screens the project picker field-ticket already has. code
  • Configure the RevenueCat webhook + swap the sandbox web key; verify one purchase unlocks a tier. owner
  • Ship the public App Store listing (privacy label, IAP "Ready to Submit"). owner
2

Prove it converts

Exit: a defined activation funnel, instrumented, with the first handful of paying design partners

  • Define + instrument the aha funnel in PostHog; narrow day-one onboarding to the one moment. code
  • Fix the marketing→app value gap: a value-first landing / demo artifact instead of a cold login wall. code
  • Recruit ~10 design-partner contractors by hand — for real data and real testimonials. owner
3

Seed the moat & the proof

Exit: the Price Index is a live, rankable page and the site shows peer proof

  • Build the permit + license ingestion engine (CSLB/DBPR free files + Socrata cities) — populates the Price Index and marketplace, kills two cold-starts. code
  • Wire testimonials + a Capterra/G2 badge + App Store rating into the marketing hero. code
  • Publish the Price Index with methodology, even sparse — turn vaporware into an asset. owner
4

Open the taps

Exit: at least one loop with a measured, positive coefficient

  • Verify the "Built with MAGE ID" badge fires on high-frequency client surfaces; measure k. code
  • Ship the content/SEO engine: comparison pages (built) + city/trade cost guides off the calculator. owner
  • Permit-triggered compliant cold email to the ingested list; double-sided referral. owner

06 — Discipline

What not to do

  • ✕
    Don't build another feature. The 141st screen doesn't move a number when the first 140 have two users. Feature work is the comfortable trap here.
  • ✕
    Don't spend on acquisition before Phase 1 ships. Paid traffic into a login wall with a broken plan-link and a fabricated PDF figure is money set on fire.
  • ✕
    Don't mass-generate SEO doorway pages. Empty "[city] construction software" pages trip Google's scaled-content-abuse policy and can suppress the whole domain. The calculator and real cost data are what earn the pages.
  • ✕
    Don't let the Price Index stay "still building." It's the entire cost-learning story's payoff. Empty, it reads as vaporware to every prospect who clicks it.
